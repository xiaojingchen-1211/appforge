# AppForge · 一句话生成可运行的应用

> 给一句自然语言需求，多路智能体并行生成**可直接运行的单文件应用**，页面内即时预览，按三个维度打分择优，结果落库持久化，支持对话式迭代与版本回滚。

## 为什么是「生成器」而不是「一个应用」

题目要求的是「AI 帮用户生成应用」，而不是「我用 AI 写了一个应用」。所以本项目的核心闭环是：

```
用户一句话需求
      ↓
多条"跑道"并行生成（同一需求，不同设计方向）
      ↓
单文件 HTML 产物 → iframe 直接运行（能点、能拖、能输入）
      ↓
三维打分排序 → 用户选用 → 落库 + 版本记录
      ↓
继续对话式迭代（基于上一版增量修改），旧版本可回滚
```

## 功能

- **赛马模式**：1 / 2 / 3 路并行生成，同一需求给出不同设计方向（极简 / 专业高密度 / 亲和）的候选
- **即时运行**：每个候选直接在 iframe 里跑起来，不是代码片段、不是截图
- **三维打分**：完成度 / 交互性 / 视觉，静态启发式评分（不额外消耗模型额度），自动排序并标出综合最高
- **持久化**：项目与版本写入数据库，刷新、换浏览器、换设备回来都还在
- **对话式迭代**：在已有版本上继续改（"把主色调换成蓝色"），生成新版本
- **版本回滚**：每次生成都留档，可一键切回任一历史版本
- **分享/导出**：任一版本可新窗口独立运行，也可下载单文件 HTML
- **降级兜底**：没有 API Key / 模型超时 / 额度耗尽时自动切到内置模板，演示流程不会断

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Next.js 15（App Router）+ React 19 | 前后端同仓库，部署简单 |
| 样式 | 手写 CSS + 设计令牌 | 不引 UI 框架，减少体积与构建风险 |
| 模型 | DeepSeek / 任意 OpenAI 兼容接口 | Key 只在服务端读，浏览器里不出现 |
| 存储 | Postgres（生产）/ JSON 文件（本地） | `DATABASE_URL` 存在时自动切 Postgres |

## 本地运行

```bash
npm install
cp .env.example .env.local   # 不填 Key 也能跑（走内置模板）
npm run dev                  # http://localhost:3000
```

### 环境变量

| 变量 | 必填 | 作用 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 否 | DeepSeek Key；不填则使用内置 mock 模板 |
| `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | 否 | 默认 `https://api.deepseek.com` / `deepseek-chat` |
| `OPENAI_API_KEY` + `OPENAI_BASE_URL` + `OPENAI_MODEL` | 否 | 任意 OpenAI 兼容服务 |
| `DATABASE_URL` | 生产必填 | Postgres 连接串；本地留空则写 `./data/store.json` |

> 密钥只放在服务端环境变量里，不进仓库、不进前端 bundle。

## 目录结构

```
app/
  page.tsx                       工作台：需求输入、候选对比、项目列表
  p/[id]/page.tsx                项目详情：运行预览、迭代、版本回滚
  api/generate/route.ts          并行生成 + 打分
  api/projects/route.ts          项目列表 / 创建
  api/projects/[id]/...          详情、迭代、选择版本、独立运行
lib/
  llm.ts                         模型调用、超时重试、降级到 mock
  prompt.ts                      生成提示词、HTML 抽取
  score.ts                       三维静态打分
  mock.ts                        离线可用的小应用模板
  store.ts / store-pg.ts / store-file.ts   存储适配层
components/PreviewFrame.tsx      沙箱 iframe 预览
```

## 关键取舍

1. **先交付、后功能**：骨架一跑通就先部署占位版，之后只做增量更新，避免最后卡在部署上归零。
2. **不用 SQLite 上 Vercel**：Serverless 没有持久磁盘，SQLite 重启即清空。所以存储层做成双适配，生产直接用 Postgres。
3. **打分用启发式而不是再调一次模型**：赛马本身已经是 N 倍调用，再加 N 次评审会让额度成倍消耗；静态特征（脚本、事件、表单、持久化、响应式）足以区分"能用"和"只是好看"。
4. **iframe 放开 same-origin**：为了让生成的应用真正能用 localStorage 存数据（"刷新后数据还在"这条硬要求）。页面里不含任何密钥，模型调用全部在服务端，风险可控。
5. **mock 不是摆设**：无 Key、断网、额度耗尽都能完整走完"输入 → 生成 → 运行 → 存库"，演示不依赖额度余额。

## 已知限制

- 生成的是单文件 HTML 应用，不产出多文件工程；复杂后端逻辑不在能力范围内
- 启发式打分只能粗略反映质量，不等同于人工评审
- 生成内容来自模型，极端情况下可能有交互瑕疵；已有版本回滚兜底
